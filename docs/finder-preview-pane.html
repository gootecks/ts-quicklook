ts-quicklook · Finder preview pane · plan

The preview pane needs a view-based extension

Finder's preview pane showed md-quicklook's live rendered document, but only a file icon for ts-quicklook. The difference is the extension kind: md-quicklook is view-based, ts-quicklook is data-based, and the plan below converts ts-quicklook.

Every claim is tagged by how it is known. Observedran it on this Mac (macOS 27.3, 26C5035r). Readsource file and line. Inferencereasoned from the other two, not confirmed. Repo state when written: ts-quicklook 0.1.0, md-quicklook 1.2.5 (VERSION file).

01What decides it

The probe hosts a QLPreviewView with one of two styles and screenshots it. InferenceFinder's pane behaves like the .compact style. Apple's documentation does not state that rule.

ObservedOf the installed third-party preview extensions, Syntax Highlight and QLMarkdown are data-based; md-quicklook is the only enabled view-based one.

InferencePane rule: a compact-style host shows a view-based extension's live view and, for a data-based extension, an icon or thumbnail instead of the reply. Not yet observed: a view-based .ts extension inside Finder's own pane. Plan step 6 is the proof.

02Evidence

ObservedFour of the five probe screenshots (swift-normal.png is omitted: it repeats the normal-style result for a second data-based extension). Window 460×620, downscaled to 720 px high for this page.

Probe source: /tmp/ql-pane-probe/probe.swift

Arguments: file, style (normal or compact), output PNG. It waits 6 s, then captures its window with screencapture -l. InferenceBuild and run line, reconstructed from those arguments:

swiftc -O /tmp/ql-pane-probe/probe.swift -o /tmp/ql-pane-probe/probe && /tmp/ql-pane-probe/probe sample.ts compact /tmp/ql-pane-probe/ts-compact.png
import AppKit
import Quartz

let args = CommandLine.arguments
let url = URL(fileURLWithPath: args[1])
let style: QLPreviewViewStyle = args[2] == "compact" ? .compact : .normal
let app = NSApplication.shared
app.setActivationPolicy(.accessory)
let win = NSWindow(contentRect: NSRect(x: 120, y: 160, width: 460, height: 620), styleMask: [.titled], backing: .buffered, defer: false)
win.title = "probe " + args[2]
let v = QLPreviewView(frame: win.contentView!.bounds, style: style)!
v.autoresizingMask = [.width, .height]
win.contentView!.addSubview(v)
v.previewItem = url as NSURL
win.orderFrontRegardless()
DispatchQueue.main.asyncAfter(deadline: .now() + 6) {
    let p = Process()
    p.executableURL = URL(fileURLWithPath: "/usr/sbin/screencapture")
    p.arguments = ["-x", "-o", "-l", "\(win.windowNumber)", args[3]]
    try? p.run(); p.waitUntilExit()
    exit(0)
}
app.run()

Scroll the diagram horizontally to see all four lifelines.

  1. 1 Finder asks Quick Look for a preview of the selected file.
  2. 2 Quick Look builds the view controller and calls loadView().
  3. 3 Quick Look calls preparePreviewOfFile(at:completionHandler:).
  4. 4 Read and tokenize the file on a global queue.
  5. 5 The attributed string returns to the main thread.
  6. 6 The text is set on the NSTextView on the main thread.
  7. 7 handler(nil) reports the first screenful ready; errors go to handler(error).
  8. 8 Quick Look hosts the live view in the pane.
  9. 9 The user drags the pane wider or narrower, or switches list, column or gallery view.
  10. 10 The host sets a new frame on the same view.
  11. 11 Autoresizing and the width-tracking text container reflow the text; there is no new request.

05How md-quicklook does it

ReadPaths are relative to md-quicklook/macos/.

  1. Declare the extension view-based.Preview/Info.plist:31-32 sets QLIsDataBasedPreview to false. The extension point is com.apple.quicklook.preview (:52-53), with 13 markdown content types (:35-50).
  2. Principal class is an NSViewController with a pinned ObjC name.Preview/PreviewViewController.swift:10-11: @objc(MDQLPreviewViewController) final class PreviewViewController: NSViewController, QLPreviewingController. The plist names it at Info.plist:54-55. preparePreviewOfFile(at:completionHandler:) is at :32; loadView() builds the view and sets preferredContentSize 1000×1200 (:18-30). The doc comment (:4-5) says the space-bar panel, the preview pane and the column view all show this controller. The class lives in a shared dylib: Preview/Launch.swift:10-17 defines mdql_preview_main, which warms up and calls NSExtensionMain, and the extension's own launcher executable only calls it (:3-5).
  3. Build the view to follow the host's size.Native/NativeDocumentView.swift:20-22: "Finder resizes the preview without asking for a new one", so the scroll view is [.width, .height]. The text view is [.width] with widthTracksTextView (:36-38). DocumentTextView.setFrameSize (:152-161) recomputes textContainerInset: side margin 14 below 500 pt, 28 below 800, else 40, content centred at a maximum width; vertical inset 14 below 500, else 28.
  4. Heavy work off the main thread; completion when the first screenful shows.Preview/PreviewViewController.swift:44 reads and parses on DispatchQueue.global(qos: .userInitiated); :58 returns to main; :73-74 sets the text and calls handler(nil). The rest of a long document is built and appended afterwards (:75-84). A read error calls handler(error) (:54). Appearance: :38-41 sets darkAqua only when the system theme is dark and the view's effective appearance is not.
  5. Thumbnails are a different extension.Thumbnail/ThumbnailProvider.swift lays out a 720×932 page (:10), draws it with the .aqua appearance (:51) and adds an "MD" badge (:45). It is always light, so a dark document in the pane comes from the preview controller. Preview/Preview.entitlements:7-21 grants read access to /, network.client and lsopen for images, WebKit and links; none of it is needed for the pane behaviour.

07Risks and open points

  • InferenceThe pane rule comes from a QLPreviewView probe, not from Apple documentation. Plan step 6 is the proof.
  • Appearance: md-quicklook sets darkAqua only when the system theme is dark and the view is not (PreviewViewController.swift:38-41). Check what the pane passes before copying that; dynamic NSColor pairs may be enough.
  • A view-based extension keeps a live view, and its process, alive while the pane shows it. Keep the 2 MB cap.
  • Read.ts resolves to the MPEG transport stream UTI system-wide (Extension-Info.plist:23-24), which is why Finder lists the files as "MPEG-…". This work does not change it.
  • File icons in rows and the gallery strip stay generic until the separate thumbnail extension exists.
